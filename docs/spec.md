# WordLoop — спецификация v1

> Статус: черновик на вычитку · Ноябрь 2026
> Документ — источник истины для всех агентов и для человека. Если поведение кода расходится со спецификацией, сначала правится спецификация (или код приводится к ней), и только потом всё остальное.

## 1. Цель

WordLoop — Telegram Mini App для заучивания английской лексики методом интервальных повторений (аналог Anki), с переводом на русский.

- **v1 делается для одного пользователя — автора.** Публичный запуск и монетизация возможны позже; архитектура не должна их закрывать, но v1 под них не оптимизируется.
- **v1 = словарь Oxford 3000.** Приложение с самого начала строится как движок с подключаемыми словарями (Oxford 5000, English Vocabulary in Use, English Phrasal Verbs in Use и др. — позже).
- Сервера нет. Всё приложение — статика на GitHub Pages; прогресс хранится в Telegram CloudStorage.

## 2. Что НЕ входит в v1

Чтобы агенты не раздували объём, явно исключено:

- обратное направление RU→EN и ввод ответа с клавиатуры (v2);
- напоминания от бота (позже, вероятно — ежедневный крон в GitHub Actions);
- свой бэкенд, БД, проверка `initData` на сервере;
- список слов с поиском (v2);
- словари кроме Oxford 3000 (движок их поддерживает, но сами словари не генерируются в рамках v1);
- извлечение словарей из учебников «in Use» — **отдельный проект**; связь с ним — только через формат файла словаря (раздел 5);
- оптимизация параметров FSRS под пользователя, журнал всех повторений;
- платежи, мультиязычность интерфейса (интерфейс только на русском);
- автотесты UI (UI проверяется руками).

## 3. Пользовательские сценарии

### 3.1 Первый запуск
1. Пользователь открывает Mini App из бота.
2. Приложение предлагает выбрать стартовый уровень: A1 / A2 / B1 / B2.
3. Слова уровней **ниже** выбранного не попадают в очередь новых (см. 6.4). Это обратимо в настройках.
4. Включён словарь Oxford 3000 с квотой 10 новых в день. Пользователь попадает на главный экран.

### 3.2 Ежедневное повторение
1. Главный экран: сколько повторений и новых слов на сегодня, кнопка «Начать».
2. Показывается лицевая сторона карточки. Пользователь вспоминает и нажимает «Показать ответ».
3. Показывается оборот. Пользователь оценивает себя одной из четырёх кнопок (6.2).
4. Следующая карточка. Когда очередь пуста — экран «На сегодня всё» с краткой статистикой.
5. На лицевой стороне **новой** карточки (которую пользователь видит впервые) есть дополнительная кнопка **«Знаю»** (6.3).

### 3.3 Работа на двух устройствах
Пользователь повторяет часть карточек на телефоне, потом открывает приложение на Telegram Desktop и продолжает. Прогресс общий; если повторения шли параллельно на устройстве с устаревшим кэшем — они сливаются без потерь (7.3).

### 3.4 Настройки
- Список словарей: включить/выключить, квота новых в день для каждого, для словарей с юнитами — «начать с юнита N».
- Стартовый уровень (повторно можно поменять).
- Порог защиты от завала N (6.5).
- Экспорт прогресса в JSON.

## 4. Карточка

### 4.1 Направление и содержимое
Только EN→RU.

| Сторона | Содержимое |
|---|---|
| Лицо | слово (или фразовый глагол), часть речи; для фразовых глаголов — шаблон (`put sth off`) |
| Оборот | 1–3 перевода через запятую (самый частотный первым), британская транскрипция IPA, один английский пример, под ним мелким шрифтом его перевод |

- Кнопка озвучки слова и примера — через Web Speech API (`speechSynthesis`), голос `en-GB`; если на устройстве нет `en-GB` — любой `en-*`; если голосов нет совсем — кнопка скрыта. Качество голоса зависит от устройства — это принято.
- Оформление следует `Telegram.WebApp.themeParams` (светлая/тёмная тема автоматически).

### 4.2 Идентичность карточки
Одно слово = одна карточка с одним прогрессом, в каком бы словаре оно ни встретилось.

- `cardId` = `нормализованное слово` + `#` + `код части речи`, например `achieve#v`, `bank#n`, `put off#phr`.
- Нормализация: нижний регистр, обрезка пробелов, схлопывание повторных пробелов. Регистр сохраняется только для имён собственных, если такие появятся (в Oxford 3000 их практически нет).
- Коды частей речи — фиксированный список в Core (`n`, `v`, `adj`, `adv`, `prep`, `pron`, `det`, `conj`, `num`, `exclam`, `modal`, `aux`, `phr`, …); точный список определяется при разборе исходного Oxford 3000 и фиксируется в Core.
- Если одна и та же пара «слово + часть речи» есть в нескольких словарях, **прогресс общий**, а содержимое берётся из словаря, стоящего выше в пользовательском списке словарей.

## 5. Формат словаря (контракт)

Этот раздел — **контракт** между WordLoop и любыми генераторами словарей, включая будущий отдельный проект по учебникам «in Use». Менять его можно только с повышением `schemaVersion` и правкой этого раздела.

### 5.1 Манифест
`wwwroot/decks/manifest.json`:

```json
{
  "schemaVersion": 1,
  "decks": [
    {
      "id": "oxford3000",
      "version": 3,
      "title": "Oxford 3000",
      "description": "3000 базовых слов английского, уровни A1–B2",
      "cardCount": 3000,
      "url": "oxford3000.json"
    }
  ]
}
```

- `url` — относительный (от манифеста) или абсолютный. Абсолютные URL уже поддерживаются кодом, хотя в v1 не используются — это задел на подключение словарей извне.

### 5.2 Файл словаря

```json
{
  "schemaVersion": 1,
  "id": "oxford3000",
  "version": 3,
  "title": "Oxford 3000",
  "ordering": "cefr",
  "units": null,
  "cards": [
    {
      "id": "achieve#v",
      "headword": "achieve",
      "pos": "v",
      "pattern": null,
      "ipa": "/əˈtʃiːv/",
      "cefr": "A2",
      "unit": null,
      "translations": ["достигать", "добиваться"],
      "example": {
        "en": "She achieved her goal of running a marathon.",
        "ru": "Она достигла своей цели — пробежала марафон."
      }
    }
  ]
}
```

| Поле | Обязательно | Описание |
|---|---|---|
| `ordering` | да | `cefr` — новые слова по уровням; `units` — по юнитам книги |
| `units` | при `ordering = units` | `[{ "id": 1, "title": "..." }]` в порядке книги |
| `cards[].id` | да | `cardId` по правилам 4.2 |
| `cards[].headword` | да | слово или фраза |
| `cards[].pos` | да | код части речи; `phr` для фразовых глаголов |
| `cards[].pattern` | нет | шаблон употребления (`put sth off`) |
| `cards[].ipa` | нет | британская IPA в слэшах; для фразовых глаголов обычно отсутствует |
| `cards[].cefr` | при `ordering = cefr` | `A1`…`C1` |
| `cards[].unit` | при `ordering = units` | id юнита |
| `cards[].translations` | да | 1–3 строки, кириллица, самая частотная первой |
| `cards[].example` | да | `en` и `ru`, обе непустые |

Тип карточки определяется набором заполненных полей, а не отдельным классом: интерфейс показывает те поля, что есть.

### 5.3 Версии
- `version` словаря растёт при любом изменении содержимого (исправили перевод — +1).
- Приложение кэширует словарь и перекачивает его, если `version` в манифесте больше закэшированной.
- Прогресс привязан к `cardId`, поэтому обновление словаря прогресс не теряет. Карточки, исчезнувшие из словаря, остаются в прогрессе, но не показываются, пока не появятся снова (в любом словаре).

## 6. Логика повторений

### 6.1 Алгоритм
- **FSRS-6** с параметрами по умолчанию, через готовую библиотеку NuGet `FSRS.Core` (порт py-fsrs). Основным кандидатом был `FsrsSharp` 5.1.3; от него отказались на срезе 2: оценка «Легко» на первом шаге обучения работает в нём как «Помню» (расхождение с py-fsrs), и он реализует предыдущую версию FSRS-5.
- Библиотека скрыта за интерфейсом `IScheduler` в Core, чтобы её можно было заменить (и для тестов — подставить детерминированную реализацию).
- Желаемая удерживаемость 0.9, максимальный интервал 3650 дней, шаги обучения по умолчанию из библиотеки.
- **Фаззинг интервалов выключен**: библиотека берёт разброс из генератора без сида, а интервалы должны быть детерминированными (одинаковыми в тестах и на обоих устройствах).
- **Срез 2 обязан проверить**, что выбранная библиотека работает в Blazor WASM (без рефлексии/зависимостей, ломающихся при тримминге).

### 6.2 Оценки
Четыре кнопки, соответствующие рейтингам FSRS: **Забыл** (Again), **Трудно** (Hard), **Помню** (Good), **Легко** (Easy). Под каждой — интервал, который она назначит («10 мин», «3 дн», …).

### 6.3 Кнопка «Знаю»
Только на новой карточке. Карточка получает состояние «выучено» с ближайшим показом через **90 дней** — одна проверка через три месяца вместо исключения навсегда. Не засчитывается в дневную квоту новых.

### 6.4 Очередь новых слов
- Каждый включённый словарь имеет **квоту новых в день** (по умолчанию 10 у Oxford 3000, 0 у остальных). Приоритет словаря — его позиция в списке; приоритет = квоты по сути (квота 10 у одного и 0 у остальных — частный случай).
- `ordering = cefr`: по уровням A1→B2 (начиная со стартового уровня пользователя); **внутри уровня — случайный порядок, детерминированный от Telegram user id**, чтобы оба устройства показывали одинаковую очередь.
- `ordering = units`: в порядке юнитов книги, внутри юнита — в порядке файла; можно начать с выбранного юнита.
- Карточка, уже имеющая прогресс (из любого словаря), в очередь новых не попадает.
- Слова ниже стартового уровня не попадают в очередь новых; при понижении стартового уровня в настройках они возвращаются в очередь.
- Счётчик «новых введено сегодня» хранится в облаке (7.2), чтобы квота соблюдалась на всех устройствах вместе.

### 6.5 Защита от завала
Если просроченных повторений больше **N** (по умолчанию **100**, настраивается), новые слова в этот день не вводятся. На главном экране показывается пояснение, почему новых сегодня нет.

### 6.6 Границы дня
День начинается в **04:00 по локальному времени устройства** (как в Anki), чтобы ночная сессия засчитывалась в «вчера». Все времена в хранилище — UTC.

## 7. Хранение и синхронизация

### 7.1 Где что лежит
| Что | Где |
|---|---|
| Файлы словарей | статика на GitHub Pages; кэш в браузере |
| Прогресс, настройки, дневные счётчики | Telegram CloudStorage — источник истины |
| Копия прогресса | localStorage — кэш для быстрого старта |

### 7.2 Лимиты CloudStorage и упаковка
Лимиты: ключ 1–128 символов (`A-Z a-z 0-9 _ -`), значение до 4096 символов, до 1024 ключей на пользователя.

- Новые (ни разу не показанные) карточки **не хранятся** — отсутствие записи = новая.
- Состояние карточки упаковывается в компактную бинарную запись (цель — не больше 16 байт): хэш `cardId` (32-битный, напр. FNV-1a), due, время последнего повторения, stability, difficulty, состояние FSRS/шаг обучения, флаги. Точный layout фиксируется в ADR при реализации среза 5 и покрывается тестами «упаковать → распаковать = исходное» с допустимой погрешностью для чисел с плавающей точкой.
- Записи группируются в «пачки» по ключам `p0`, `p1`, … (base64), раскладка — по хэшу, чтобы запись одной карточки меняла ровно одну пачку.
- Коллизии хэшей между всеми известными словарями проверяются генератором словарей (8.3) и тестом в Core.
- Отдельные ключи: `settings` (JSON), `day` (дата + число введённых новых), `meta` (версия формата хранения).
- Оценка: ~16 байт → ~22 символа base64 → ~180 карточек на ключ → Oxford 5000 целиком ≈ 28 ключей. Запас по лимитам большой.

### 7.3 Слияние
- При старте: показать данные из localStorage сразу, затем прочитать облако и **слить**.
- Слияние **по карточкам**: для каждой карточки побеждает запись с более поздним временем последнего повторения. Для `day` — побеждает более поздняя дата, при равной дате — максимум счётчика. Для `settings` — запись с более поздней меткой изменения.
- Перед каждой записью в облако — прочитать пачку, слить, записать.
- Записи в облако — пакетно и с задержкой (debounce ~2 с после последней оценки) и обязательно при сворачивании/закрытии Mini App.
- Алгоритм слияния — чистая функция в Core, покрыта тестами, включая сценарий «два устройства, параллельные повторения».

## 8. Генерация контента (ContentGen)

### 8.1 Вход
- Исходный список Oxford 3000 (слово, часть речи, уровень CEFR) лежит в репозитории как `data/source/oxford3000.csv`.
- Получение этого CSV из официального PDF Oxford — часть среза 3 (разбор PDF скриптом, результат коммитится).

### 8.2 Процесс
- Консольное приложение `WordLoop.ContentGen` вызывает Claude API (Message Batches API — дешевле и подходит для тысяч записей) пачками.
- Для каждой записи генерируются: 1–3 перевода, британская IPA, пример и его перевод. Определения и примеры Oxford не используются и не копируются — весь контент генерируется заново.
- **Идемпотентность и кэш:** результаты по каждой записи кэшируются локально (`data/cache/`, не в git); повторный запуск генерирует только отсутствующие/упавшие/изменённые записи. Поменялся промпт или формат — можно перегенерировать всё одной командой с флагом.
- Ключ API — только через `dotnet user-secrets` или переменную окружения. **Никогда не в репозитории** (репозиторий публичный).
- Выход: `src/WordLoop.Web/wwwroot/decks/oxford3000.json` + обновлённый `manifest.json`.

### 8.3 Валидация
Валидатор словаря живёт в Core (используется и генератором, и тестами):
- все обязательные поля заполнены, `translations` — 1–3 элемента;
- русские поля содержат кириллицу, английские — нет;
- IPA обрамлена слэшами и состоит только из допустимых символов IPA;
- пример на английском содержит заглавное слово или его словоформу (простая эвристика по основе; провал — не ошибка, а «подозрительная запись»);
- `cardId` уникальны в словаре, соответствуют правилам 4.2, нет коллизий 32-битных хэшей;
- соответствие схеме раздела 5.

Результат — ошибки (словарь не собирается) и **отчёт о подозрительных записях** `data/reports/<deck>-suspicious.md` для ручной вычитки.

## 9. Интерфейс

Экраны v1:
1. **Первый запуск** — выбор стартового уровня.
2. **Главный** — на сегодня: повторений / новых; кнопка «Начать»; пояснение, если сработала защита от завала.
3. **Повторение** — карточка, «Показать ответ», четыре оценки с интервалами, «Знаю» на новых, озвучка.
4. **Готово на сегодня** — сделано за сегодня.
5. **Статистика** — сегодня сделано/осталось, выучено всего, прогноз числа повторений на 7 дней.
6. **Настройки** — словари (вкл/выкл, квоты, стартовый юнит), стартовый уровень, порог N, экспорт прогресса.

Экран загрузки (до старта Blazor): вместо стандартной заглушки шаблона (синий круг с процентами) — свой экран в стиле WordLoop: название/логотип и анимированный индикатор, отражающий реальный прогресс загрузки (`--blazor-load-percentage`). Требования: только HTML/CSS (и при необходимости короткий inline-скрипт) прямо в `index.html` — без шрифтов, картинок и библиотек, которые грузятся отдельно и замедляют холодный старт; цвета — из темы Telegram (`--tg-theme-*`) с нейтральным фолбэком вне Telegram; без «мигания» при переходе к первому экрану приложения.

Навигация через `BackButton` Telegram; основное действие экрана — через `MainButton`, где это естественно.

Экспорт: JSON со всем прогрессом и настройками. Способ выдачи файла в WebView Telegram проверяется на срезе 7 (кандидаты: `WebApp.downloadFile`, если доступен в версии клиента; иначе — копирование JSON в буфер обмена).

## 10. Технический стек и структура

- .NET 10, Blazor WebAssembly (standalone), тримминг включён, AOT не используется (замер на срезе 1, `docs/adr/0001-blazor-wasm-stack.md`).
- Telegram Web App JS SDK — через тонкий слой JS-интеропа в `WordLoop.Web/Interop`.
- Хостинг — GitHub Pages (публичный репозиторий), сборка и деплой — GitHub Actions по пушу в `main`.

```
WordLoop.sln
src/
  WordLoop.Core/         доменная модель, IScheduler + обёртка FSRS, упаковка и слияние
                         состояния, построение дневной очереди, валидатор словарей.
                         Чистый C#, без зависимостей от UI, браузера и Telegram.
  WordLoop.Web/          Blazor WASM: экраны, интероп с Telegram SDK и Web Speech,
                         адаптеры хранилища (CloudStorage, localStorage).
    wwwroot/decks/       манифест и файлы словарей
  WordLoop.ContentGen/   консоль: CSV → Claude API → словарь + отчёт
tests/
  WordLoop.Core.Tests/   xUnit
data/
  source/                исходные списки (в git)
  cache/                 кэш ответов API (не в git)
  reports/               отчёты о подозрительных записях (в git)
docs/
  spec.md                этот документ
  adr/                   записи архитектурных решений
.github/workflows/       ci.yml (сборка + тесты), deploy.yml (Pages)
```

Особенности GitHub Pages для Blazor (учесть на срезе 1): сайт проекта живёт по пути `/WordLoop/` → правильный `<base href>`; файл `.nojekyll` (иначе папка `_framework` не публикуется); `404.html` для SPA-маршрутов.

## 11. Критерии приёмки v1

v1 **готова**, когда:
1. Все ~3000 записей Oxford 3000 сгенерированы, проходят валидацию без ошибок, отчёт о подозрительных записях разобран вручную.
2. Mini App открывается из бота на Android и на Telegram Desktop и следует теме Telegram.
3. Холодный старт на телефоне автора — **не более 5 секунд**, повторный (из кэша) — не более 2 секунд.
4. Работает полный дневной цикл: новые по квотам, повторения по FSRS, «Знаю», защита от завала, граница дня в 04:00.
5. Прогресс, сделанный на телефоне, виден на десктопе; после очистки кэша Telegram прогресс восстанавливается из облака.
6. Параллельные повторения на двух устройствах сливаются без потерь — покрыто тестами Core.
7. Экспорт прогресса в JSON работает.
8. Логика Core покрыта тестами, CI зелёный, деплой автоматический по пушу в `main`.

v1 **проверена**, когда автор пользуется приложением 14 дней подряд и не хочет его бросить. Только после этого обсуждается v2.

Если на срезе 1 холодный старт Blazor не укладывается в 5 секунд даже с триммингом/AOT/сжатием — работа останавливается и решение о стеке пересматривается.

## 12. Порядок поставки (вертикальные срезы)

Каждый срез заканчивается работающим, задеплоенным состоянием.

1. **Скелет.** Пустое Blazor-приложение собирается в Actions, деплоится на GitHub Pages, открывается в Telegram через бота, показывает имя пользователя и следует теме. Замер холодного старта.
2. **Повторение на 20 захардкоженных словах.** FSRS через `IScheduler`, четыре оценки с интервалами, прогресс в localStorage.
3. **ContentGen на 100 словах.** Разбор исходного списка в CSV, генерация, валидатор, отчёт. *Независим от 1–2, может идти параллельно.*
4. **Словари и манифест.** Загрузка словаря из файла вместо хардкода, кэш и версии, общая идентичность карточек между словарями.
5. **CloudStorage.** Упаковка, пачки, синхронизация, слияние; ADR с layout записи.
6. **Дневная логика.** Квоты по словарям, защита от завала, «Знаю», граница дня, первый запуск с выбором уровня, детерминированный порядок.
7. **Настройки, статистика, экспорт, экран загрузки.**
8. **Полная генерация Oxford 3000** и вычитка отчёта.

Задачи ведутся в GitHub Issues; один срез может быть разбит на несколько задач, каждая — на одну сессию агента.
