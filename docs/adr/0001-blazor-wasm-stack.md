# 0001. Остаёмся на Blazor WebAssembly, без AOT

- Статус: принято
- Дата: 2026-11-08
- Задача: #5 (срез 1, go/no-go точка из spec, раздел 11)

## Контекст

Spec (раздел 11) требует холодный старт Mini App на телефоне автора не дольше 5 секунд и повторный (из кэша) — не дольше 2 секунд. Если Blazor WASM не укладывается в это даже с триммингом/AOT/сжатием, стек пересматривается. Раздел 10 откладывал решение об AOT до этого замера.

Состояние на момент замера:
- Release-сборка с триммингом (`PublishTrimmed`), без AOT, без `InvariantGlobalization`.
- GitHub Pages отдаёт `.wasm`, `.dat` и `.js` в gzip; по сети при холодном старте уходит порядка 2,5–3 МБ (`dotnet.native.wasm` ≈ 1,2 МБ, `System.Private.CoreLib.wasm` ≈ 0,6 МБ, один шард ICU ≈ 0,2–0,3 МБ). Brotli Pages не отдаёт.
- Повторный старт: ресурсы `_framework/` берутся из Cache Storage рантайма Blazor.

## Решение

Автор открыл Mini App из бота на Android и Telegram Desktop: имя пользователя показывается, тема Telegram применяется, холодный и повторный старт укладываются в критерии раздела 11.

- Продолжаем на .NET 10 Blazor WebAssembly (standalone).
- Тримминг остаётся включённым.
- AOT не включаем: старт и так в пределах критериев, а AOT увеличивает объём загрузки.
- Дополнительное сжатие (brotli через `loadBootResource`) и `InvariantGlobalization` не вводим.

## Последствия

- Объём загрузки — бюджет: новые зависимости в `WordLoop.Web` и `WordLoop.Core` оцениваются по влиянию на холодный старт.
- Если старт деградирует, рычаги по порядку: `InvariantGlobalization` (минус шард ICU) → brotli-файлы с декодером в `loadBootResource` → AOT. Каждый — с повторным замером на телефоне.
